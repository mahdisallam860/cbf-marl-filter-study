## (a) The 433 filter-on INFEASIBLE trials

**Method.** For each trial the saved pre-step state of the attempted period (which infeasibility prevented) and the saved raw actor command. Reproduction: the unchanged `CBFQPFilter` at alpha* = 10 was called once on these saved values (the code promotes the logged float32 values to float64, so 'logged dtype' and 'float64' inputs coincide on this code path); its verdict was only compared with the logged one. Rows were rebuilt with the identical construction (`bmatch.barrier_rows`) in float64, and independently in float32 arithmetic. Normalised slack = (a.u - b)/|a| (negative = violated; solver tolerance 1e-9). Stand-off h* = row margin / row gain (obstacle delta_o/alpha; pair (delta_ij/2)/(alpha/2)). Binding row = the enabled row of an infeasible robot with the most negative zero-command slack.

**Reproduction: 433 of 433 trials** (433 of 433 infeasible robots) are reproduced as infeasible by the recomputation, with the same infeasible robots. Every infeasible trial has exactly one infeasible robot.

**Declared near-boundary diagnostic** (fixed before computing): |zero-command slack of the binding row| <= 1e-6 AND |h - h*| <= 1e-3 m^2. Met by **410 of 433** reproduced infeasible robots. The remaining 23 miss only the slack threshold (their slack lies between -5e-6 and -1e-6; h - h* is below 1e-7 m^2 for all).

**Reading.** Every reproduced infeasible state has its binding row at the stand-off h* to within about 4e-8 m^2, with the zero command violating that row by between 8e-9 and 5e-6 (normalised), and float32 rounding of the same formulas changing the sign in about a fifth of cases. This is **consistent with numerical sensitivity near the boundary**: with alpha*.dt = 1 the decay term can bring a barrier to its stand-off in about one period, after which the zero command sits within rounding of the row. It is not proof of the cause; in particular it does not show that a tolerance rule would remove the events or what the robots would then do.

**s2_early, K = 3, trial 646** (final_test (saved per-step initial poses)): min obstacle cover barrier h_o = -0.00777 m^2 at t = 0 (body surface gap to that obstacle 0.0870 m; min robot-robot body gap 0.2416 m; robot-robot barriers non-negative). The nearest obstacle centre is 0.7695 m from the nominal start centroid, just beyond the sampler's exclusion radius edge_clear + D_o + slot_radius = 0.75 m.

**Likely cause** (from the sampler code, `scenario.sample_layout`; not modified): obstacle placement is checked against the NOMINAL start centroid (distance >= edge_clear + D_o + slot_radius), while the start poses carry position noise (sigma = 0.03 m) and heading noise (sigma = 0.15 rad) that move the robots' barrier points; only robot-robot barrier-point spacing is checked on the noisy poses. A robot's noisy barrier point can therefore start inside an obstacle cover disc although its body is clear. **Recorded as an A5 exception** (1 of 27,000 final-test trials; 0 of the 1,200 saved validation layouts). Neither Lemma 1 nor any filter-on statement covers that start; the trial is kept unchanged in every confirmatory number.
